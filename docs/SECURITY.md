# Security model

Kobold is hardened for a single-user developer workstation, not a server and not a pentest appliance.

## Trust boundaries

Fedora owns kernel, firmware integration, SELinux policy, systemd, NetworkManager, GNOME, firewalld, Podman and core packaging. Kobold prefers upstream security defaults unless a stricter workstation policy has a concrete benefit and acceptable usability cost.

## Host exposure

The default firewalld zone is `drop` with no services, ports, protocols, forwarding, masquerading or rich rules pre-opened. Anaconda may add `ssh` after installing a bootc payload, so a one-time unit idempotently restores the composed Kobold zone before firewalld and NetworkManager start, then records completion in persistent system state. SSH server is not installed; the OpenSSH client remains available. Avahi, printer daemon, GNOME remote desktop/user sharing and ModemManager are absent or disabled.

## Kernel policy

See `/etc/sysctl.d/60-kobold-security.conf`. Controls are chosen to reduce information disclosure and common local/network attack surface without breaking Flatpak, rootless Podman, libvirt or normal GNOME operation.

User namespaces remain available. Global IP forwarding is not forced off because libvirt/container networking can legitimately require it. USB is not disabled and USB autosuspend is not forced.

## Privacy policy

- NetworkManager connectivity checking is disabled.
- DHCP hostname transmission is disabled by default.
- Wi-Fi scan MAC randomization is enabled and associated Wi-Fi MAC defaults to stable-per-SSID randomization.
- LLMNR and mDNS are disabled; Avahi is absent.
- GeoClue is masked and GNOME location is off by default.
- rpm-ostree count-me service is disabled/masked when present.
- systemd-coredump does not persist process memory dumps.

These controls reduce unsolicited information sharing; they do not claim anonymity against a network operator, browser fingerprinting, websites, ISP, or compromised applications.

## Secure Boot

Kobold does not replace Fedora's kernel, shim or boot chain. Image signing (Cosign) authenticates the OCI artifact; it is separate from UEFI Secure Boot. Do not weaken Fedora's Secure Boot configuration for branding.

## RPM repository trust

Kobold does not retain Fedora Workstation's optional third-party repository bundle. `fedora-workstation-repositories` and `fedora-third-party` are removed with the package manager before repository allowlisting is enforced. Google Chrome, RPM Fusion and COPR opt-in repository files must not survive the build. Final `.repo` files must be RPM-owned by `fedora-repos` or `fedora-repos-archive`; filename prefixes are not trusted as an allowlist. The Microsoft VS Code repository exists only during the build transaction and is removed before final validation.

The Fedora Silverblue base itself is accepted only from the fixed `quay.io/fedora/fedora-silverblue` namespace and by immutable digest. Kobold image signatures are a separate trust layer generated by the Kobold GitHub OIDC release workflow.
